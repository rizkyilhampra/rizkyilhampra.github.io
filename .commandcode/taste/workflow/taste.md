# Workflow

- Prefers leveraging web_fetch to pull in official documentation (upgrade guides, release notes, docs, GitHub repos/READMEs) when planning migrations, researching breaking changes, or evaluating third-party tools/libraries — provides URLs directly rather than having the agent guess. Confidence: 0.85
- Explicitly asks the agent to research by fetching (web_fetch) whenever there is doubt, rather than guessing or assuming — e.g., verifying live behavior of a deployed site against reported issues. Confidence: 0.80
- Challenges unverified claims that something is "best practice" or "common practice" — expects such claims to be backed by actual research (web search + fetching authoritative sources, e.g., official vendor docs) before being asserted. Confidence: 0.80
- Prefers working directly on the main branch for personal/solo projects, skipping feature branches. Confidence: 0.70
- Follows the Conventional Commits specification for commit messages (e.g., `chore:`, `feat:`, `fix:`). Confidence: 0.85
- Expects the agent to clean up after itself — kill background processes it started and remove tmp/scratch files it created when finishing or abandoning a task. Confidence: 0.75
- When cleaning up after a task, only remove tmp/scratch files and kill background processes — do NOT remove, revert, or delete repo files (even ones created during the session), which should be left in place unless explicitly asked. Confidence: 0.85
- Asks the agent to survey/review the current working directory and relevant files before making changes, rather than editing blind. Confidence: 0.7
- Wants generated/baked artifacts verified by actually executing the original upstream tool end-to-end, not just by reasoning or re-implementing logic — e.g., re-runs the real `img2art` CLI pointed at the source jpg and byte-diffs its output against the committed artifact, in addition to cell-by-cell JSON-vs-raw checks. Confidence: 0.8
- Prefers skipping lint/verification passes when an edit is small and low-risk (e.g., pure JSX reorder) — explicitly asks to cut short extra validation loops; only verify when the change is genuinely risky or the user requests it. Confidence: 0.75
- Likes iterations driven by quick successive directives — both layout moves ("put the portrait on top", "now move it to the right side", expecting related classes like `md:flex-row`, `flex-1`, `md:ml-auto` to be adjusted rather than left stale) and numeric tuning of generator constants ("how about 1.8?" → interpret, apply the SCALE tweak, regenerate, and confirm resulting dimensions in one pass). Confidence: 0.7
- When regenerating generated artifacts, expects a backup of the previous artifact for before/after diffing, plus structural comparison of old vs new output (keys, dimensions, glyph streams) to confirm exactly what changed. Confidence: 0.7
- Hand-edits source files mid-session (e.g., tweaked SocialIconRow className in App.jsx, later moved the portrait to the right side themselves: "i put on right one") — re-read files before editing to detect external changes, and preserve the user's manual edits rather than overwriting them. Confidence: 0.75
- Delegates open-ended design decisions by explicitly asking for the agent's recommendation (e.g., "what's your recommendation for light mode?") and expects a reasoned proposal grounded in the site's design system, then applied directly. Confidence: 0.6
- After a recommendation is applied, follows up asking whether alternative approaches exist (e.g., "is there any tho instead use bg-foreground in light mode?") — expects options enumerated with concrete trade-offs (artifact size, aesthetic shift, per-theme rendering behavior) so they can choose, rather than a single take-it-or-leave-it answer; then picks one directly by number ("now try of this 1."). Confidence: 0.7
- Iterates on layout via revert-then-restructure cycles: asks to revert an earlier restructure, then issues a new combined directive (wrap h1+typewriter in a section AND vertically center the text group against the portrait) — bundle multi-part layout feedback into one pass. Confidence: 0.6
- Questions the agent's implementation choices with short "why/how-about" probes ("why you tho it's need like hook? how about if this, ...") and expects a candid answer: admit when the user's simpler alternative is better, adopt it, and explain why it beats the original approach — not a defense of the initial plan. Confidence: 0.75
- For state-changing git operations (e.g., `git add` staging), wants the agent to only report/recommend which files to stage — explicitly "just tell me, don't do it" — keeping the actual mutation under their control unless they ask for it. Confidence: 0.8
